WITCH TOWER - GITHUB WINDOWS BUILD
==================================

The repository now contains a GitHub Actions workflow that builds:

    WitchTower.exe

The executable is a 64-bit Windows console application. Python does not
need to be installed on the computer that runs the finished EXE.

FILES ADDED
-----------
.github/workflows/build-windows-exe.yml
    GitHub Actions workflow.

WitchTower.spec
    PyInstaller configuration. Includes the complete art/ directory.

requirements-build.txt
    Build-only dependency pin for PyInstaller.

.gitignore
    Ignores local build output, Python caches, and player save JSON files.

HOW TO BUILD ON GITHUB
----------------------
1. Create a GitHub repository.

2. Put the CONTENTS of this witch_tower_rpg folder at the repository root.
   In other words, GitHub should show files like:

       main.py
       game.py
       WitchTower.spec
       art/
       .github/

   Do not put the whole project inside another extra folder unless you also
   update the workflow paths.

3. Commit and push to the main branch.

4. Open the repository on GitHub.

5. Open:
       Actions -> Build Windows EXE

6. A build runs automatically after a relevant push to main.

   You can also start one manually:
       Actions -> Build Windows EXE -> Run workflow

7. When the job finishes, download WitchTower.exe from the workflow run.

SAVES IN THE EXE BUILD
----------------------
The packaged game writes its save folder beside the executable:

    WitchTower.exe
    saves/
        savegame.json
        safe_haven.json
        run_meta.json

This allows normal autosaves and the protected 20-floor death checkpoint
to survive after closing the EXE.

The source-code version still writes saves inside the project folder.

GITHUB RELEASES
---------------
The workflow now has two output modes.

NORMAL BUILD
------------
A push to main, or a manual "Run workflow", builds:

    WitchTower.exe
    WitchTower.exe.sha256

These are available from the completed Actions workflow run as the
"WitchTower-Windows" artifact.

VERSIONED RELEASE
-----------------
To publish a repository Release containing the EXE, push a version tag
beginning with "v".

Example:

    git tag v0.1.0
    git push origin v0.1.0

GitHub Actions will then:

1. Build WitchTower.exe.
2. Generate WitchTower.exe.sha256.
3. Keep both files as a normal Actions artifact.
4. Create a GitHub Release named:

       The Witch Tower v0.1.0

5. Attach:

       WitchTower.exe
       WitchTower.exe.sha256

6. Generate release notes automatically.

If the workflow is rerun for a tag whose Release already exists, it
replaces the EXE/checksum assets instead of creating a duplicate Release.

IMPORTANT TERMINOLOGY
---------------------
GitHub Packages is a package-manager registry for supported ecosystems
such as NuGet, npm, Maven, RubyGems and containers. A standalone Windows
EXE is therefore published as a GitHub Release asset instead.

WORKFLOW PERMISSION
-------------------
The workflow declares:

    permissions:
      contents: write

This gives the repository GITHUB_TOKEN permission to create Releases.
No personal access token is required for the Release step.


ACTIONS ARTIFACT FORMAT
-----------------------
The normal "WitchTower-Windows" Actions artifact contains both:

    WitchTower.exe
    WitchTower.exe.sha256

GitHub packages those two files together as a workflow artifact.

The versioned GitHub Release is different: WitchTower.exe and its SHA256
file are attached to the Release individually as raw downloadable assets.
